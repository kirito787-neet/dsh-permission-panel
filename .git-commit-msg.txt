fix(permissions): reach unopened sessions; add bulk editing

Two more silent failures in the workspace-permissions panel, plus the
requested bulk-select feature.

SYMPTOM 1 - "some sessions still show unavailable".

The panel lists every session, but reads each preset from the sessions list
snapshot's `projectionValues`. That snapshot only carries projections the
Host has ALREADY pushed: the live control baseline, or cached list hints
read from the persisted checkpoint. A session the user has never opened
usually has neither, so `projectionValues.permissions` is absent, `current`
is null, and the row is computed unusable - looking broken when nothing was
wrong with it.

The panel now calls `sessions.refreshProjections(id)` for every listed
session. That goes through `remote.session.projections`, answered Host-side
by `observeSession`, which never activates an Agent.

Deliberately NOT `retain()`: retaining materializes a client scope and
starts the session's history `open()`, so doing it per row would open every
conversation in the sidebar. Projections are the purpose-built cheap read
for "show me metadata about sessions I have not opened".

The effect keys on the id LIST rather than the snapshot object: snapshot
identity changes on unrelated fields (running flags, retention counts), and
re-reading every projection then would hammer the Host for nothing. Already
answered sessions short-circuit inside the manager.

SYMPTOM 2 - "该会话暂时无法下发指令（尚未装载）".

The panel dispatched through `sessions.binding(id)?.session` then
`session.command(line)`. `binding(id)` only returns a binding for a scope
that ALREADY exists - it never creates one; `retain()` does. So the panel
could only ever drive the handful of sessions that happened to be open, and
every other row refused with exactly the reported message.

Dispatch now goes through `remote.commands.execute(sessionId, line, [])` -
the same surface the official ui-plan chip uses. It takes the id directly,
and the Host resolves it via `resolveAgent(sessionId)`, which RESUMES a cold
session on demand, so an unopened session is a valid target with no
client-side scope, history open, or retention involved. A binding lookup
remains as a documented fallback for a carrier composing sessions without
`remote.commands`.

While implementing this I introduced - and then found - a scoping bug worth
recording: `dispatchCommand` was placed at module scope but read
`permissionPanel`, a `const` declared inside `apply`. The name does not
resolve there, so every dispatch threw `permissionPanel is not defined`
before sending anything: a silent "nothing happens" on every row. The
namespace is now captured into panel state at bind time and passed in.

BULK EDITING.

Per-row checkboxes, a select-all beside the heading, and a bulk bar showing
the selected count, a preset picker, and Apply/Clear.

- Only usable rows get a checkbox. Offering one on a row that cannot change
  would let the user assemble a selection that Apply silently skips, so the
  count and the outcome would disagree.
- Apply stays disabled until a preset is chosen; a pre-armed bulk control is
  one stray click from rewriting a batch.
- Full access asks ONCE for the batch, not per session - asking ten times
  for the same acceptance just trains the user to click through it.
- Sequential, not `Promise.all`: each switch is a distinct Host command, and
  firing many at once buys nothing while making failures unattributable.
- Partial success is reported as partial, naming the failing sessions (first
  five, remainder folded into a count). Claiming success when sessions
  refused would be worse than the original bug - the user would believe a
  change that never happened.
- The selection is intersected with the live rows on read, so a session that
  disappears or is archived cannot leave the count claiming rows that are
  gone.

TESTS. All seven mutations verified to be caught:
- reverting dispatch to the binding path;
- removing the projection read;
- bulk apply ignoring the selection;
- bulk apply arriving pre-armed;
- archived sessions having their projections read;
- a per-row binding returning (static guard);
- disabling the by-id dispatch path (static guard).

Two guards were strengthened after mutation testing showed they were
worthless as first written. The bulk case originally ticked EVERY row, which
makes "selected" indistinguishable from "all manageable rows" - dropping the
selection filter left the test green. It now ticks one of two, with the
unticked row at the same preset so an ignored selection must produce a
second command. The archived-session fixture originally carried a projection,
so the "archived are not read" assertion passed vacuously; it now omits one.

Stubs were also corrected to match real React: `useState` supports a lazy
initializer, and `useSyncExternalStore` actually calls `subscribe` (it
previously skipped straight to the snapshot, so a component whose
subscription was never wired still looked healthy). Both gaps were found by
this round's code.
